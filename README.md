# Журнал решений · прототип 0.4

Рабочий прототип памяти команды: встречи, решения, их основания и история, проверка записей, действия и Jira. Два сценария показывают один продукт в разных контекстах — у команды дизайн-системы и у продуктовой команды банковского приложения.

[Демо дизайн-системы](https://decision-journal-pilot.kenymook.chatgpt.site/) · [Демо банковского приложения](https://decision-journal-pilot.kenymook.chatgpt.site/?demo=bank#/meetings). Доступ к сайту управляется отдельно.

В шапке можно переключить сценарий. У каждого свои встречи, решения, справочники и локальные изменения; выбранная тема оформления общая.

[Повторить заставку загрузки](https://decision-journal-pilot.kenymook.chatgpt.site/?intro=1). При первом входе в сессии участники созвона постепенно раздувают голову персонажа; на 100% появляется мультяшный «пух», название и интерфейс. Полный цикл заставки занимает 10 секунд, поддерживает пропуск и настройку уменьшения движения. Повторные входы не получают искусственной задержки.

## Запуск

Требуется Node.js 20+.

```sh
git clone https://github.com/kenymook/team-memory.git
cd team-memory
```

```sh
npm ci
npm run build
npm test
```

Для локального просмотра, если установлен Python 3:

```sh
python3 -m http.server 4173 --directory dist
```

Откройте `http://localhost:4173`. Приложение рассчитано на размещение в корне сайта.

Каталог `dist/` обслуживается любым статическим HTTP-сервером. Приложение использует React и esbuild.

## Структура интерфейса

Базовые компоненты находятся в `vendor/ui/src`: Button, IconButton, TextField, Select, Badge, Tag и Checkbox. Таблицы, панели, вкладки и остальные композиции приложения собраны в `src/main.jsx`; их оформление — в `src/app.css`.

Светлая и тёмная темы генерируются из `vendor/ui/tokens.json` командой `node vendor/ui/generate-theme.mjs`. Если Inter не установлен, используется системный шрифт. Стили приложения задают видимый клавиатурный фокус, контраст интерактивных элементов и нейтральное выделение боковой навигации.

Заставка загружается отдельным небольшим пакетом до React. `src/loading-scene.js` содержит SVG-сцену, `src/loading-screen.css` — оформление и движение, `src/loading-timeline.js` — модель фаз, `src/loading-screen.js` — загрузку приложения и переход. Проценты передают ход заставки, а не долю скачанных байтов; 100% и открытие интерфейса разрешены только после готовности модуля, стилей и первого монтажа приложения.

## Сценарий дизайн-системы

В журнале 48 встреч: исходные восемь и ещё 40 обсуждений компонентов с 3 августа по 12 ноября 2026 года. Полный набор содержит 70 решений, 26 тем, 30 действий и 19 демонстрационных Jira-задач. Есть повторные обсуждения одной темы, пересмотры договорённостей, закрытые вопросы, непроверенные записи и задачи в разных состояниях. Дополнительный набор находится в `src/ds-scale-demo.js` и автоматически добавляется к старым сохранениям без сброса пользовательских изменений.

В карточках встреч показаны вымышленные участники и их роли: кто принёс продуктовый сценарий, кто уточняет контракт компонента и кто отвечает за реализацию. Поиск включает имена и роли. Компоненты, команды-потребители и границы Web/Android/iOS сохраняют собственный контекст; история решений доступна из обычных списков и карточек.

## Банковский сценарий

Начните со списка встреч, поиска или фильтра по направлению. В разделе «Решения» можно найти действующую договорённость и открыть её карточку. Например, `DEC-B05` объясняет, почему после таймаута перевода команда показывает ожидание подтверждения; из карточки доступны причина, фрагмент обсуждения, прежнее `DEC-B01` и задача `DEMO-201`.

Восемь встреч показывают работу исследователя, аналитика, дизайнера, мобильного и backend-разработчиков, QA и продуктового менеджера. Направления: переводы, история операций, онбординг, уведомления, поддержка и планирование расходов. Поиск находит также участников и их роли.

В «К разбору» можно проверить новую запись и сравнить похожие задачи. Аналитика объединяет повторные обсуждения одной проблемы, отделяет гипотезы от подтверждённых проблем и объясняет сигналы внимания.

Сценарии настроены в `src/scenarios.js`; банковский набор — в `src/bank-demo.js`. Общие расчёты используют справочник выбранного набора. Параметр `?demo=bank` открывает банковское демо напрямую; URL без параметра сохраняет исходное демо.

## Что реализовано

- Светлая и тёмная темы; переключатель в шапке сохраняет выбор. До первого переключения используется тема системы.
- Компактная навигация, шапка высотой 48 px и профиль «Руслан Каутаров».
- Рейл 64 px с квадратными кнопками 40×40 px; таблица встреч сохраняет видимые название и статус на узких экранах.
- Теги синхронизированы с фильтром; четыре группы вкладок имеют связанные доступные панели и клавиатурное управление.
- Поиск по названиям, summary, тексту расшифровки, именам и ролям участников; фильтры по компоненту или продуктовому направлению, команде, платформе и периоду.
- Основные списки разбиты на страницы по 12 записей. Поиск, фильтры, счётчики и аналитика учитывают весь набор; возврат из карточки сохраняет страницу списка.
- Карточка встречи с участниками и ролями, редактирование меток, переход к конкретному фрагменту.
- Проверка и корректировка текста решения, причина, область применения, история замены.
- Компактные карточки решений: непроверенная запись отмечена рядом с ID, причина встроена в текст, метки и действия собраны в нижнюю строку. «Заменено» и «Отменено» сохраняют отдельные отметки.
- Отдельное завершение разбора встречи после проверки записей.
- Содержательное сравнение кандидатов Jira, подтверждение и исправление связи, форма демонстрационной задачи, отметка «Задача не требуется» с причиной и возврат к разбору.
- Общий контекст действий для аналитики и очереди; прямой переход от показателя к соответствующим действиям.
- Возврат по истории карточек с сохранением вкладки и прокрутки; исправление решения возвращает исходную встречу к проверке.
- Метрики, рассчитываемые из записей, автоматические объяснимые сигналы и ручные отметки.
- Раздельное локальное сохранение сценариев в текущем браузере. Данные исходного демо не перезаписываются при переходе в банковское.
- Старые сохранения получают отсутствующих участников и исправления исходных демотекстов с сохранением пользовательских правок, статусов и связей.
- Набор из 40 дополнительных встреч ДС добавляется один раз; банковский сценарий остаётся независимым.
- Проверка импорта встречи `schemaVersion: 1`; повторный ID не создаёт дубль.

## Граница прототипа

Все исходные данные, цитаты, роли участников и задачи DEMO вымышлены. Серверной базы, совместной работы, авторизации рабочих пользователей, приёма вебхуков, автоматического извлечения и подключения к Jira здесь нет. Изменения сохраняются в localStorage текущего браузера. Импорт принимает только встречу; структурированные темы, решения и действия пока демонстрируются на согласованном наборе. Рабочий адаптер к агенту и Jira проектируется по реальным форматам и правам доступа внутри разрешённой среды.

Продуктовые правила и следующий этап: [docs/PRODUCT_SPEC.md](docs/PRODUCT_SPEC.md).
